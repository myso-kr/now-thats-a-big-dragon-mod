# Now THAT'S a Big Dragon! — 외부 주입형 모드

> ## ⚠️ 읽고 시작하세요
>
> **비공식 팬 제작 모드입니다.** 게임 *Now THAT'S a Big Dragon!* 의 개발사·퍼블리셔 및
> Valve 와 아무런 관련이 없고, 승인이나 후원을 받지 않았습니다.
> 모든 상표와 저작권은 각 권리자에게 있습니다.
>
> **게임을 정당하게 구매한 분만 사용할 수 있습니다.** 이 저장소에는 게임의 원문 텍스트나
> 에셋이 들어 있지 않습니다. 번역을 적용하려면 본인의 게임 사본이 있어야 합니다.
>
> **게임 파일은 수정하지 않습니다.** 런처가 메모리 상의 응답만 바꿉니다. 런처를 끄면
> 게임은 원본 그대로이고, 스팀 파일 무결성 검사에도 걸리지 않습니다.
>
> **세이브가 손상될 수 있습니다.** 치트와 오토플레이는 게임이 예상하지 않는 상태를
> 만들 수 있습니다. 처음 실행하기 전에 세이브를 백업하세요.
>
> **스팀 도전과제·통계.** 치트 위젯은 기본값으로 도전과제·통계 전송을 차단합니다.
> 이 차단을 끄고 치트를 쓰면 정상적으로 얻지 않은 도전과제가 스팀 계정에 영구히 남습니다.
>
> **원격 디버깅 포트가 열립니다.** 이 모드는 게임을 `--remote-debugging-port=9223` 으로
> 실행합니다. 이 포트에는 인증이 없어서 같은 PC 의 다른 프로그램이 붙어 게임을 조작하거나
> 화면을 읽을 수 있습니다. 사용하는 동안에만 켜 두세요.
>
> **게임이 업데이트되면 깨질 수 있습니다.** 패치는 번들 구조에 의존합니다.
> 확인한 버전은 아래 "지원 게임 버전" 표에 있습니다.
>
> **무보증.** 있는 그대로 제공되며, 사용으로 생긴 어떤 손해에도 책임지지 않습니다.
> 권리자의 요청이 있으면 이 저장소는 즉시 내려갑니다. (help@myso.kr)


게임 파일을 **전혀 수정하지 않고** 한글패치와 치트 위젯을 적용합니다.
Electron 의 원격 디버깅(CDP)으로 붙어서 응답을 가로채는 방식이라,
런처를 끄면 게임은 원본 그대로 돌아갑니다. 스팀 파일 무결성 검사에도 걸리지 않습니다.

## 요구사항

- Node.js 22 이상 (내장 `WebSocket`/`fetch` 사용, 외부 패키지 없음)
- 게임 설치 경로가 기본값과 다르면 `BIG_DRAGON_DIR` 환경변수로 지정

## 사용법

```bash
node launcher.js              # 게임을 직접 실행하고 패치 적용
node launcher.js --attach     # 스팀으로 이미 실행한 게임에 붙기
node launcher.js --no-cheat   # 한글패치만
node launcher.js --no-ko      # 치트 위젯만
```

`--attach` 로 쓰려면 스팀 → 게임 속성 → 실행 옵션에 다음을 넣습니다.

```
%command% --remote-debugging-port=9223
```

런처 창을 닫으면 패치가 해제됩니다. 게임을 끄면 런처도 함께 종료됩니다.

## 실행 전 확인

게임이 이미 떠 있으면 런처가 실행을 거부합니다. Electron 단일 인스턴스 락 때문에
새 프로세스가 기존 것에 넘기고 즉시 죽어 `--remote-debugging-port` 가 적용되지 않는데,
그런데도 런처는 붙는 데 성공한 것처럼 보이기 때문입니다. 게임을 완전히 종료한 뒤
다시 실행하거나 `--attach` 를 쓰세요.

## 치트 위젯

게임 안에서 **F8** 로 열고 닫습니다.

탭 세 개로 나뉩니다. 머리말을 끌어 위치를 옮길 수 있습니다.
(자동 클릭은 치트가 아니라 플레이 행위라 오토플레이로 옮겼습니다 — 아래 오토플레이 절 참고.)

| 탭 | 기능 |
|---|---|
| 자원 | 골드 · 목재 · 광석 · 식량 · 마나 값 설정, +1천 / +10만 / +1천만 / ×10, 게임 속도 0.25~8× (화면 + 시뮬레이션) |
| 업그레이드 | 88종을 한국어 이름으로 나열. 분류·검색 필터, 항목별 −/+/최대, 전부 해금 · 전부 최대 · 되돌리기 |
| 고급 | 일시정지 / 재개 / 저장, 전역 변수 JSON 편집, 내부 이벤트 122종 `emit`, 도전과제 차단 |

콘솔에서도 `window.__bd_cheat` 로 같은 기능을 쓸 수 있습니다
(`setRes`, `setLevel`, `startDragon`, `stopDragon`, `upgrades()` 등).

**도전과제 차단은 기본 켜짐입니다.** 치트로 얻은 수치가 스팀 도전과제·통계로 나가지 않게 막습니다.

> 차단을 끄면 치트로 만든 기록이 스팀에 그대로 올라갑니다. 의도한 경우에만 끄세요.

### 동작 방식

- **자원 · 업그레이드**는 세이브 슬롯 zustand 스토어를 직접 씁니다. 업그레이드는 게임과
  같은 규칙(`multiplier += bonusPerOwned × 변화량`)으로 파생값을 맞추므로 효과가 실제로 적용되고,
  `purchaseLimit` 을 넘지 않습니다.
- **자동 클릭**은 게임 자체 이벤트(`click_game_dragon` / `stop_click_game_dragon`)를 그대로 씁니다.
  '손목 치료'를 보유했다면 게임이 알아서 최대 속도로 연타합니다.
- **새 자동 클릭**은 씬의 새 액터를 찾아 게임의 `killBird()` 를 호출합니다.

### 게임 속도

Excalibur 의 `timescale` 은 **화면(액터·애니메이션)만** 빠르게 합니다. 골드 생산이나
이벤트 같은 시뮬레이션은 `tickLength`(기본 1000ms) 주기의 별도 타이머가 돌립니다.
그래서 속도 조절은 **둘 다** 바꿉니다.

| 배속 | tickLength | 초당 틱 |
|---|---|---|
| 1× | 1000ms | 1 |
| 2× | 500ms | 2 |
| 4× | 250ms | 4 |
| 8× | 125ms | 8 |

**상한은 8× 입니다.** 16× (63ms) 는 후반 챕터에서 틱 처리가 주기를 넘겨 메인 스레드가
포화되고, 창을 끄는 순간 먹통이 되거나 게임이 멈춥니다. 콘솔로 더 큰 값을 넣어도
`MAX_SPEED` 로 잘립니다.

**`tickLength` 는 세이브에 저장되는 값입니다.** 그대로 두면 런처를 끈 뒤에도 남으므로,
1× 로 되돌릴 때 · 창을 닫을 때 · 위젯이 뜰 때 각각 원래 값으로 복구합니다.
그래도 이상하면 자원 탭의 **`틱 1000ms 로 복구`** 버튼을 누르면 됩니다.

**속도 감시기.** 배속을 올리면 틱마다 하는 일이 그만큼 늘어납니다. 유닛과 업그레이드가
많은 후반 챕터에서는 **틱 처리가 주기보다 오래 걸려 메인 스레드가 포화**됩니다.
그러면 입력과 화면이 멈추고(창을 끌면 그대로 먹통), 결국 게임이 응답하지 않습니다.
메모리가 부풀어 보이는 것은 원인이 아니라 이 포화의 증상입니다.

그래서 배속이 1× 를 넘는 동안 2초마다 **"요청한 만큼 실제로 처리되고 있는지"** 를 봅니다.

| 판정 | 기본값 | 조치 |
|---|---|---|
| 실제 틱 / 목표 틱 | 60% 미만 | 한 단계 감속 (8→4→2→1) |
| 프레임 | 20fps 미만 | 한 단계 감속 |
| 힙 상한 | 1200MB | 1× 로 복귀 |
| 배속 시작 대비 증가 | 400MB | 1× 로 복귀 |
| 액터 수 | 1500개 | 1× 로 복귀 |

개입하면 패널이 닫혀 있어도 화면 아래에 알림이 뜨고, 열려 있으면 슬라이더와
프리셋 버튼도 바뀐 속도를 따라갑니다
(`치트: 초당 3.1틱 (목표 8) — 속도를 4× 로 낮췄습니다`).
틱이 아예 0 인 상태(메뉴 · 대사 · 컷신)는 포화가 아니므로 오판하지 않습니다.

`window.__bd_cheat.guardLimits` 로 조정할 수 있고, `window.__bd_cheat.diag()` 로
현재 힙 · 액터 수 · 액터 종류별 개수를 바로 확인할 수 있습니다.

## 오토플레이

게임 안에서 **F9** 로 열고 닫습니다. **Shift+F9** 는 패널을 열지 않는 즉시 정지입니다.

게임을 다시 켜면 오토플레이는 **항상 꺼진 채로 시작합니다.** 맨 윗줄이 꺼져 있으면
붉은 기로 물들고 `오토플레이 꺼짐 · 눌러서 시작` 으로 바뀌니, 그 줄을 눌러 켜면 됩니다.
상태 줄은 `실행 중` 일 때만 초록이고 `꺼짐 · 대기 · 보류` 는 경고색입니다 —
셋 다 지금 아무 일도 하지 않는다는 뜻입니다.

패널은 시작/중지와 최소 설정만 담당하고, 켜지면 사람 개입 없이 스스로 굴러갑니다.
드래곤·새 자동 클릭은 시작과 함께 항상 돕니다(스위치 없음) — 보스의 마지막 1 HP 는
틱이 멈춘 `coup_de_grace` 구간이라 **클릭으로만** 깎을 수 있어, 끄면 거기서 교착됩니다.

| 스위치 | 범위 | 기본 |
|---|---|---|
| 구매 | 유닛 25종 · 업그레이드 88종 · 자원 계열 | 켬 |
| 전투 | 마나 충전 · 영감 발동 | 켬 |
| 대사 | 넘기기 · 선택지 자동 선택 | 켬 |


설정은 셋입니다 — **예비 골드**(자동화와 사용자가 같은 골드를 두고 경쟁하는 유일한 지점),
**선택지 처리**(불가역 결정에 대한 통제권), 그리고 **클리어 후 동작**.
나머지 정책 값은 내부 기본값으로 숨깁니다.

### 클리어 후 동작

보스를 잡으면 게임 틱이 멈춥니다. 그때 무엇을 할지 고릅니다.

| 모드 | 동작 |
|---|---|
| 멈춤 | 거기서 대기합니다. **기본값** — 진행이 되돌려지지 않기를 바라는 경우 |
| 반복 | 같은 챕터를 다시 돌립니다. 반복할 챕터를 따로 지정할 수도 있습니다 |
| 다음 챕터 | 다음 챕터로 넘어가고, 더 없으면 현재 챕터를 반복합니다 |

"반복"과 "다음 챕터"는 **새 회차로 되돌리는 동작**입니다. 되돌리기 전에 항상
세이브 스냅샷을 `snapshots/` 에 남기므로, 원치 않는 전환이 일어나면 거기서 복구할 수 있습니다.

전환은 언제나 게임의 챕터 메뉴 버튼을 누릅니다. `change_level` 을 직접 발행하면
슬롯 저장·재수화가 빠져 게임이 상태 불일치 복구 경로를 타고 보스가 1 HP 로 바뀝니다.

### 무엇을 보고 값을 매기는가

번들을 역해석해 게임의 산출 계산식을 복원하고 그 위에서 판단합니다. 주요한 것만:

- **화염 브레스 생존** — 사망은 확률이 아니라 결정론적 비율입니다(전사 100% · 마법사 75% ·
  도적/음유시인/성직자 50%, 엘프·투석기·건물은 죽지 않음). 유닛 가치를 "지평선"이 아니라
  "살아 있는 시간"으로 잽니다. 그래서 브레스 직전에는 전사 점수가 저절로 무너져
  별도 금지 규칙이 필요 없습니다.
- **실효 발동 주기** — 산출표 값은 "1회 발동당"이고 주기는 유닛마다 1~300틱입니다.
  나누지 않으면 대학을 전사보다 300배 높게 봅니다.
- **효과 방향이 부호와 어긋나는 업그레이드** — `sonicBarrier` · `fastHands` · `encore` ·
  `manaBoost` · `piercedEardrums` · `manaSurge` 는 `bonusPerOwned` 가 0이거나 음수라
  일반 공식에서 영원히 탈락합니다. 각각 제 효과로 따로 값을 매깁니다.
- **블랙리스트** — `cacofonix`(1골드 고정가에 부대를 기절시킴)와 던전 전용 11종은 후보에서 뺍니다.
- **자기교정** — 20초 창마다 예측과 실측을 대조해 계열별 보정계수를 학습합니다.
  예측만큼 돌려주지 않는 계열은 격리하고, 산출이 살아나면 풉니다.
  `window.__bd_auto.calib()` 로 현재 계수를 볼 수 있습니다.

설계 근거 전문은 아키텍처 문서에 있습니다:
<https://claude.ai/code/artifact/4696666d-d095-452d-967d-a0b0cdbee8a4>

### 어떻게 판단하는가

세 개의 시계로 돕니다. **플래너를 게임 틱에 묶지 않는 것이 핵심**입니다 — 그러면 계획 비용이
배속에 비례해 8배속에서 메인 스레드 포화를 오토플레이가 스스로 만듭니다.

| 시계 | 주기 | 역할 |
|---|---|---|
| 실행기 | 게임 `tick` | 수위 비교 후 행동 1건. 대부분의 틱은 O(1) 로 끝남 |
| 플래너 | 벽시계 1Hz | 후보 재평가 · 상위 8개 계획 |
| 감독자 | 750ms | 대사 · 영감 · 마나 · 자원 · 챕터 · 정지 조건 |

점수는 `지평선 H 누적기여 ÷ 비용` 단일 축입니다. 유닛·업그레이드·공학이 같은 저울에
올라가므로 카테고리별 우선순위표가 필요 없습니다. 생산 체인(주둔지→전사, 군사평의회→주둔지)은
재귀로 접어 넣고, 지평선은 `H = clamp(3 × 잔여HP/DPS, 60, 900)` 으로 잡습니다.

DPS 는 재구현하지 않고 **게임이 이미 계산해 둔 표**(`__bd_stats`)를 읽습니다. 업그레이드와
영감 배수가 모두 반영된 유닛 1기당 한계 산출이 거기 들어 있습니다.

### 자원 챕터

유닛별 자원 유지비 21종 전표를 내장해, **적자를 만드는 구매를 사전에 차단**합니다.
사후에 해고하는 것보다 언제나 싸기 때문입니다. 그래도 런웨이가 60초 아래로 떨어지면
효율이 낮은 유닛부터 생산을 끄고(가역적), 600초 위로 회복되면 효율 높은 것부터 되켭니다.

### 대사

게임 전체 선택지 18개를 전수 확인해 최적해를 고정했습니다.

| 대사 | 선택 | 이유 |
|---|---|---|
| `trading` | 런웨이 최저 자원 | 가장 먼저 마를 자원을 산다 |
| `pope_visit` | 헌금 | 거절하면 드래곤이 회복된다 |
| `invasion_start` | 다수 방어 | 소수 방어는 전멸, 몸값은 골드 85% 손실 |
| `catapult` | 지불 | 고양이 개조로 피해량 10배 |
| `king_dungeon` | 뇌물 | +1e12 골드. 뇌물을 받아도 `king_dungeon_2` 로 최종전에 갈 수 있다 |

식별은 이벤트가 아니라 **선택지 텍스트 서명**으로 합니다. 우리가 번역해 넣은 텍스트라
안정적이고, 주입 시점에 이벤트 버스가 없어도 동작합니다. 서명이 맞지 않으면 클릭하지 않고
보류합니다.

### 안전장치

무인 운영이 전제라 "사용자가 이상을 눈치채고 끈다"에 기댈 수 없습니다.

- **허용 목록** — 오토플레이는 `buy_generator` / `buy_upgrade` / `activate_inspiration` /
  `change_level` / `show_upgrade` / `unlock_upgrade` 만 발행할 수 있고,
  `clear_save` · `restart_level` 은 통로 자체를 막았습니다.
  뒤의 두 신호는 게임 UI 가 구매 직후에 보내는 것으로, 이게 없으면 업그레이드 트리가
  영원히 열리지 않습니다(리듀서는 해금을 해 주지 않습니다).
- **정지 조건** — 값 오염(`NaN`/`Infinity`), 알 수 없는 챕터, 20분 무진행,
  데드맨 타이머(6시간). 감속이 아니라 **정지**이고 자동 재개하지 않습니다.
- **자원 고갈은 정지가 아닙니다** — 농부·나무꾼·광부는 자원이 말라도 계속 돌아
  자기회복 경로가 있습니다. 런웨이가 30초 아래로 떨어지면 유지비를 더 얹는 구매만
  잠그고 생산자를 사서 빠져나옵니다. 10분간 회복하지 못할 때만 멈춥니다.
- **런처 측 외부 워치독** — 엔진이 1초마다 심박을 남기고, 런처가 밖에서 지켜봅니다.
  6초 끊기면 CDP 로 오토플레이를 정지시키고 배속을 1× 로 되돌립니다.
  **렌더러가 굳으면 게임 안의 감시기도 함께 죽으므로, 이것이 유일한 실질 안전장치입니다.**
- **세이브 스냅샷** — 시작 · 5분마다 · 챕터 전환 직전 · 정지 직전에 슬롯 스토어를 떠서
  런처가 `snapshots/` 에 파일로 남깁니다(최근 20개).
- **속도 제한** — 초당 20액션 상한, 재진입 금지, 발행 직전 `context === 'in_game'` 재확인.

### 콘솔 API

```js
window.__bd_auto.start() / .stop()
window.__bd_auto.snapshot()      // 현재 읽기 모델
window.__bd_auto.candidates(snap, H)   // 후보와 점수
window.__bd_auto.runway(snap)    // 자원이 마르기까지 남은 초
window.__bd_auto.snapshots()     // 세이브 스냅샷 링 버퍼
```

## 한글패치

- UI 문자열 **486/572** 번역 (나머지 86개는 `+`, `x`, `%` 같은 기호와 주석 키라 번역 대상 아님)
- 캐릭터 대사 **32/32** 파일 번역 (`patch/dialogs/ko/*.ink`)
- 게임이 지원하는 언어는 en/fr/de/pt/tr 뿐이라, **en 슬롯을 한국어로 덮어쓰는** 방식입니다.
  한국어 시스템에서는 언어 자동감지가 실패해 기본값 en 으로 떨어지므로 그대로 한국어가 나옵니다.
- 시간 단위(초·분·시간·일·개월·년)는 i18n 테이블이 아니라 별도 Scale 객체에 있어 따로 치환합니다
- 한글 픽셀 폰트를 **게임에 직접 실어 줍니다.** 설치할 필요가 없습니다 (아래 참고)

### 폰트

원본 두 폰트에는 한글 글리프가 없습니다. 그래서 **갈무리**를 `@font-face` 로 실어
원본 폰트 바로 뒤에 폴백으로 붙입니다. 라틴 문자는 원본이, 한글은 갈무리가 그립니다.
폰트는 게임에 함께 실려 나가므로 설치할 필요가 없습니다.

**픽셀 정렬.** 게임이 쓰는 본문 크기는 12 / 18 / 24 / 36px 입니다. 원본 본문 폰트는
6 px/em 격자라 이 크기들에서 디자인 픽셀이 각각 2 / 3 / 4 / 6 화면픽셀로 딱 떨어집니다.
한글 폰트도 같은 격자에 올리려면 `디자인픽셀 = font-size / 6` 이어야 하는데,
gcd(12,18,24,36) = 6 이므로 **6 보다 잘게 쪼갤 수 없습니다.**
그래서 한글의 획을 늘리려면(= 격자를 키우려면) 글자도 그만큼 커질 수밖에 없습니다.

| 본문 후보 | 격자 | size-adjust | 라틴 대문자 대비 | 부분투명 픽셀(18px) |
|---|---|---|---|---|
| **Galmuri7** | 7px | **133.33%** | **1.17배** | 55.6% |
| Galmuri9 | 9px | 166.67% | 1.50배 | 54.7% |
| Galmuri11 | 11px | 200% | 1.83배 | 57.4% |
| ~~Galmuri9~~ | 9px | ~~133.33%~~ | ~~1.22배~~ | ~~69.9%~~ (격자 어긋남) |

격자를 어긋내면 크기와 상세도를 동시에 잡을 수 있을 것 같지만, 실측하면 부분투명 픽셀이
12~15%p 늘어 눈에 띄게 뭉갭니다. 그래서 정렬을 지키고 **영문에 가장 가까운 Galmuri7** 을 씁니다.

제목은 High_Birth(9 px/em)에 Galmuri9(10 px/em)를 `size-adjust: 111.11%` 로 맞춰
격자가 1:1 이고 **한글 높이가 라틴 대문자와 정확히 같습니다(1.000배).**

측정값 (라틴 대문자 높이 = 1.0 기준):

| | 12px | 18px | 36px |
|---|---|---|---|
| 본문 한글/라틴 | 1.167 | 1.167 | 1.167 |
| 제목 한글/라틴 | 1.000 | 1.000 | 1.000 |
| 줄 상자 (라틴 = 한글) | 24 / 22 | 36 / 32 | 72 / 64 |

**줄 높이 고정.** 한글 폰트를 키우면 줄 간격이 밀려 UI 가 흔들립니다. 이를 막기 위해
`ascent-override` / `descent-override` 로 줄 상자를 원본과 똑같이 고정했습니다.
주의할 점은 `size-adjust` 가 이 오버라이드까지 함께 키운다는 것이라, `patch/bundle.js`
에서 배율로 나눠 상쇄합니다. 그 결과 12 / 18 / 24 / 36px 모든 크기에서 한글 줄 상자가
라틴과 1px 오차 없이 같습니다.

**바꾸려면** `config.js` 의 `KOREAN_FONTS` 에서 `file` 과 `koPxPerEm` 만 고치면 됩니다
(Galmuri7 → 8, Galmuri9 → 10, Galmuri11 → 12). size-adjust 와 메트릭 보정은 자동입니다.
세 폰트 모두 `patch/fonts/` 에 들어 있습니다.

두 폰트 다 없는 글자는 맑은 고딕으로 떨어집니다 (`config.js` 의 `SYSTEM_FALLBACK`).

폰트는 **SIL Open Font License 1.1** 입니다. 전문은 `patch/fonts/OFL-Galmuri.txt`,
저작권자는 Lee Minseo (quiple). 재배포할 때 이 라이선스 파일을 반드시 함께 두세요.

### 번역 고치기

UI 문자열은 `patch/i18n.ko.json`, 대사는 `patch/dialogs/ko/*.ink` 를 직접 고치고
런처를 다시 실행하면 됩니다. `patch/i18n.en.json` 은 원문 대조용입니다.

대사 파일은 Ink 스크립트라서 **본문과 선택지 라벨만** 손대야 합니다.
`# 태그`, `VAR` 선언, `{변수}`, `=== 크노트 ===`, `-> 이동`, `* + -` 마커를 건드리면
대사가 통째로 안 뜹니다. 고친 뒤에는 구조 검사를 돌리세요.

```bash
node tools/check-dialogs.js
```

부분 번역 파일을 병합할 수도 있습니다.

```bash
node tools/merge-ko.js patch/ko-part1.json
```

병합할 때 `{{placeholder}}` 가 원문과 일치하는지 자동 검사합니다.

에셋 번들이 바뀌므로 원문을 다시 뽑습니다. 기존 번역은 보존됩니다.


## 동작 원리

1. 게임을 `--remote-debugging-port=9223` 으로 실행합니다.
2. CDP 의 `Fetch` 도메인으로 `gemshell://` 커스텀 프로토콜 응답을 가로챕니다.
   - `assets/index-*.js` → 번들 안의 영어 i18n 테이블 12종을 한국어로 교체
   - `assets/style-*.css` → 한글 폰트 `@font-face` 추가 + 폰트 스택에 폴백 추가
   - `fonts/bd-ko-*.woff2` → 실어 준 한글 폰트 파일로 응답
   - `dialogs/en/*.ink` → 한국어 대사 파일로 바로 응답 (원문을 읽을 필요가 없어
     요청 단계에서 처리합니다. 다른 언어 대사는 건드리지 않습니다.)
3. `Page.addScriptToEvaluateOnNewDocument` 로 치트 위젯을 문서 로드 전에 주입합니다.
4. 번들 패치 때 zustand 스토어 팩토리를 감싸, 생성되는 모든 스토어를
   `window.__bd_stores` 에 `saveKey` 별로 등록합니다.
5. 위젯은 이 브리지와 게임이 원래 노출한 전역(`global_game_store`,
   `___EXCALIBUR_DEVTOOL`, `events_manager`, `achievements_handler`)을 함께 씁니다.

### 자원이 왜 브리지를 거쳐야 하나

`global_game_store.state.globalVariables.gold` 는 Ink 대사 분기용 **미러**입니다.
여기에 값을 써 넣으면 화면에는 잠깐 반영되지만 다음 동기화(약 0.5초)에 원래 값으로
덮어써집니다. 실제 자원은 세이브 슬롯별 zustand 스토어(`slot_<슬롯>_currency`)가
들고 있고, 위젯은 그쪽의 `setGold`/`setWood`/... 를 호출합니다.
슬롯이 여러 개면 Ink 미러 값과 가장 가까운 스토어를 활성 슬롯으로 판단합니다.

디스크에 쓰는 파일은 이 폴더 안의 것뿐입니다. 게임 폴더는 읽기만 합니다.
